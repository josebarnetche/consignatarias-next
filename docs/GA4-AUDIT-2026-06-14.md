# GA4 Tracking Audit & Fixes — 2026-06-14

Property: `G-6CZMZH9S6Y`. Deep audit of the PRO funnel readability + other surfaces, with all code fixes applied. Remaining items require GA4 Admin (UI) config — see §3.

## 1. What was wrong

| Problem | Impact |
|---|---|
| `pro_upgrade` was **dead code** (defined, never called) | No terminal conversion event — funnel had no bottom |
| Conversions sent `plan_price`, not GA4-reserved `value`/`currency` | GA4 computed **zero revenue / ARPU / conversion value** |
| Custom params never registered as dimensions | Events countable but **not segmentable** (config gap, §3) |
| `signup` dead | Activation funnel (signup→DT-e→PRO) had no first step |
| `cta_click` dead | Landing CTA performance invisible |
| `claim_submit` / `claim_success` dead; forms fired `claim_cta` on **submit** | Claim/B2B funnel half-blind + mislabeled |
| Double `page_view` on first load (inline `config` + provider) | Inflated pageviews; distorted bounce/engagement/per-page |
| No env guard | localhost + Vercel preview polluted the **production** property |
| `checkout_redirect` only on 1 of 3 checkout buttons | Asymmetric mid-funnel measurement |
| 4 ad-hoc `trackEvent('…')` calls bypassing the typed layer | Untyped, undocumented, typo-prone |

## 2. Code fixes applied (this commit)

- **`src/lib/analytics.ts`** — hostname env-guard on every event (`PROD_HOSTS`); `trackPageView` now emits a manual `page_view` event (pairs with `send_page_view:false`); `trackCheckoutStart` + new `trackCheckoutRedirect` carry `value`+`currency:'ARS'`; **`trackProUpgrade` now fires the GA4-recommended `purchase`** event with `value`/`currency`/`transaction_id`/`items`; typed wrappers added for the ex-ad-hoc events (`trackDteDemoStart`, `trackMilestoneShare`, `trackBulkIcsExport`); `trackEvent` param type widened to allow ecommerce `items`.
- **`src/app/layout.tsx`** — GA script gated on `VERCEL_ENV === 'production'`; inline config sets `send_page_view:false` (kills the duplicate initial pageview).
- **`src/components/AnalyticsProvider.tsx`** — new global `SignupTracker` fires `sign_up` once on the `?signup=1` post-auth redirect, deduped + URL-stripped.
- **`src/app/auth/callback/route.ts`** — flags brand-new accounts (`created_at` < 5 min) with `?signup=1` on redirect.
- **`src/components/UpgradeConfirmTracker.tsx`** — passes `transaction_id` (rebill subscription id) into the purchase event.
- **`UpgradeButton` / `SubscribeButton` / `MobileStickyCTA`** — all 3 now fire `checkout_redirect` (typed) right before redirecting to Rebill.
- **`ClaimForm` / `FrigorificoClaimForm`** — fixed mis-wire: `claim_submit` on submit + `claim_success` on success (was `claim_cta` on submit).
- **`LiveHero`** — home hero CTAs fire `cta_click` (`acceder_terminal`, `ver_directorio`, `en_vivo`, `calendario_semana`).
- **DTEUploader / MilestoneBadges / RematesClient** — ad-hoc events replaced with the typed wrappers.

## 3. Manual GA4 Admin steps (cannot be done in code)

**a) Mark Key Events** (Admin → Events → toggle "Mark as key event"):
`purchase`, `checkout_start`, `checkout_redirect`, `sign_up`, `claim_success`, `pro_prompt_click`.

**b) Register Custom Dimensions** (Admin → Custom definitions → Create custom dimension; scope=Event) so params become segmentable in reports/explorations:
`plan_name`, `conversion_source`, `prompt_context`, `prompt_variant`, `source`, `taste_context`, `categoria`, `signup_method`, `consignataria_slug`, `consignataria_name`, `destination`, `auction_type`, `province`, `link_type`, `filter_type`, `is_first_dte`, `badge_name`, `ai_engine`.

**c) Mark `purchase` as the conversion for revenue** — with `value`/`currency` now sent, GA4 Monetization reports (Total revenue, ARPPU) populate automatically once `purchase` data flows.

**d) (Optional) DebugView** — verify the funnel end-to-end on a staging payment using GA4 DebugView before trusting the dashboards.

## 4. Funnel now readable end-to-end

`cta_click` → `pro_prompt_view` → `pro_prompt_click` → `planes_view` → `checkout_start` → `checkout_redirect` → **`purchase`** (DB-confirmed, with revenue value).

Activation: `sign_up` → `dte_page_view` → `dte_upload_start` → `dte_ocr_complete` → `dte_save`/`activation_first_dte` → `dte_milestone`.

Claim/B2B: `claim_cta_click` → `claim_submit` → `claim_success`.
