## #9 — LCP / Performance audit (estático)

**Estado:** ✅ Server-first / 🟡 algunos issues

### ✅ Buenas señales

- **Todos los `page.tsx` son Server Components** (ningún `'use client'` al root). Bundle JS chico en first paint.
- **`next/font` con `display: 'swap'`** ya configurado para Inter.
- **`@vercel/speed-insights`** instalado → recolectando CWV en producción.
- **13 `<Image>` components**, 100% con `alt` definido.
- **OG image dimensions** explícitas (1200×630) en layout root.
- **Vercel Functions / Fluid Compute** → cold starts mejorados.

### 🟡 Issues a tunear

1. **Solo 1 imagen con `priority`** en todo el sitio (`/el-corredor`). Las hero images de homepage + listing pages no tienen priority, lo que perjudica LCP cuando son above-the-fold. Recomendación: marcar `priority` en:
   - `src/app/page.tsx:175` (logo nav — ok skipear)
   - `src/app/page.tsx:800` (hero principal — VERIFICAR si es above-the-fold)
   - `src/app/(terminal)/el-corredor/page.tsx:140` (ya tiene ✓)
   - Cualquier hero específico de landing pages

2. **Heavy deps no tree-shaken en algunos paths:**
   - `tesseract.js` (3–8 MB) — ya está `dynamic import` per commit history. Verificar que no lo carga en initial bundle de páginas no-OCR.
   - `jspdf` — solo se usa para `/exportar`, debería ser dynamic import.
   - `framer-motion` v12 (60+ kB) — verificar que no se importa en homepage.
   - `lucide-react` (huge en barrel imports) — usar named imports siempre.

3. **`unoptimized` flag** en perfiles consignataria/frigorifico:
   ```tsx
   <Image src={profile.logoUrl} fill unoptimized />
   ```
   Se está saltando la optimización de Next.js para los logos. Justificable si las URLs son externas inestables, pero **revisar si se puede optimizar via `loader` custom** + caching.

4. **`/remates/[slug]` SSG bajo carga**: con ~380 remates activos generando 380 páginas, el build genera mucha data. Verificar `dynamicParams=false` para evitar SSR runtime cost. Ya está en producción según CLAUDE.md ✓.

## Findings pendientes (no shipados hoy)

### 🟡 Para próximo sprint

1. **Image sitemap separado** (`/sitemap-images.xml`): Next.js sitemap API soporta el campo `images` por entry. Implementar para frigorificos profiles (438 logos MAGYP) y consignatarias profiles (74 logos) ayudaría a indexación de imágenes verticales.

2. **Per-route opengraph-image.tsx para más routes** clave:
   - `/mercado` — mostrar INMAG number live
   - `/el-corredor` — mostrar cover del mes
   - `/frigorificos/[slug]` — mostrar tipo de habilitación, provincia, capacidad

3. **Cross-links contextuales en perfil consignataria** (ya hay `relatedConsignatarias` pasado al client, pero verificar que se renderiza en UI). Faltarían:
   - Link a `/remates/{provincia}` desde profile
   - Link a frigorificos de la misma provincia

4. **Pagination en directorios** si crecen: actualmente `/consignatarias` y `/frigorificos` son listings completos. Si pasan de 500 items, considerar paginación con `rel=next/prev`.

### 🔵 Estratégico / requiere decisión

5. **City × type combos** (`/remates/{ciudad}/{tipo}`): podría crear long-tail traffic, pero también dilución del índice. NO recomendado sin GSC data que justifique queries reales.

6. **Year recap evergreen**: "Mercado ganadero Argentina 2025" como página editorial. Requiere agregación de datos del año + redacción. Mejor lanzar después del cierre Dic 2026.

7. **Backlink hunting** (off-page): consignatarias.com.ar tiene pocos enlaces inbound. Plan: outreach a INTA, CRA, asociaciones agropecuarias provinciales con menciones a metodología INMAG.
